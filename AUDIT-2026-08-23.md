# Weather-Arb Technical Audit

**Repo:** `github.com/ShmelkyDoodle/weather-betting` (private) · **HEAD:** `1e485d7` · **Audited:** 2026-08-23

A single-process async Python system that trades Kalshi daily-high temperature markets for 7 US cities. Currently running **unattended in dry-run (paper) mode** on a Mac mini since 2026-07-22. It is measuring, not trading real money.

**Scale:** ~12.0k LOC in `weather_arb/`, ~2.7k LOC across 26 offline test files, 3 runtime dependencies, 192 MB SQLite ledger.

> **Note for external review:** no credentials are committed. `.env`, `*.pem`, `*.key` are gitignored; only `.env.example` is tracked. Auth is described below by mechanism only.

### Runtime topology

`main.py` runs one asyncio process supervising long-lived tasks. Any task returning early is treated as a crash and tears down the process — the loops must stay parked on `stop_event` when idle.

| Task | Role |
|---|---|
| `metar_poller` | METAR every 45 s → validated running `T_max` → fires `on_new_high` |
| `arb_evaluator` | evaluates both strategies per market |
| `market_discovery` | daily bucket discovery + settlement-rule verification |
| `settlement` | grades settled markets, writes `market_results` |
| `websocket` | Kalshi `orderbook_delta` stream (needs credentials; REST polling otherwise) |
| `onemin_augmenter` | only when `WA_ENABLE_1MIN_LOCKIN` (currently off) |
| `heartbeat` | ~10 min JSON status line |

Deployed as 6 launchd agents: `tracker`, `verify`, `weekly`, `watchdog`, plus optional `divergence` and `logrotate`.

**Design stance worth flagging for integration:** the codebase is deliberately dependency-light and vendors its own math (isotonic regression, normal CDF, Kelly, fee model) rather than pulling scipy/sklearn/pandas. Any modular enhancement that drags in a scientific stack is a real architectural change, not a drop-in.

## 2. Data & API integrations

### 2.1 Kalshi

**Base:** `https://api.elections.kalshi.com/trade-api/v2` (configurable via `KALSHI_REST_BASE_URL`)

| Method | Path | Auth | Used by |
|---|---|---|---|
| GET | `/markets` | no | discovery |
| GET | `/markets/{ticker}` | no | market info, rules, result |
| GET | `/markets/{ticker}/orderbook` | no | REST book fallback (depth 32) |
| GET | `/series/{series}/markets/{ticker}/candlesticks` | no | backtest only |
| POST | `/portfolio/orders` | **yes** | place limit order |
| DELETE | `/portfolio/orders/{id}` | **yes** | cancel |
| GET | `/portfolio/orders` | **yes** | open-order reconciliation |
| GET | `/portfolio/orders/{id}` | **yes** | single order lookup |
| GET | `/portfolio/balance` | **yes** | equity |

**Authentication** — `KalshiSigner` (`market_client.py:114`). RSA-PSS request signing: the string `timestamp_ms + METHOD + path` (path only, no query string) is signed with the account's RSA private key using **PSS / MGF1-SHA256**, base64-encoded, sent as three headers:

```
KALSHI-ACCESS-KEY        <key id>
KALSHI-ACCESS-SIGNATURE  <base64 PSS signature>
KALSHI-ACCESS-TIMESTAMP  <unix ms>
```

Key material comes from `KALSHI_API_KEY_ID` + `KALSHI_PRIVATE_KEY_PATH` (a PEM path, never inline). `cryptography` is the only reason that package is a dependency. **Absent credentials, `Settings.dry_run` auto-enables and orders are journaled to SQLite but never transmitted.**

**WebSocket** — `KALSHI_WS_URL`, subscribes to the `orderbook_delta` channel for tracked tickers. Auth headers are generated for the WS path via the same signer. Auto-reconnect with exponential backoff capped at 30 s.

**Orderbook parsing** — two paths into the same `OrderBook` type:
- REST `_orderbook_from_kalshi()`: `yes`/`no` arrays → `PriceLevel(price_cents, size)`, sorted descending. Kalshi quotes **both sides as bids**; a YES ask is derived as `100 − no_bid`.
- WS `_apply_snapshot()` / `_apply_delta()`: maintains `{price: size}` dicts per side under an asyncio lock, deleting levels that go `<= 0`.

**Rate limiting:** `TokenBucketRateLimiter` (rate + burst) on the client, plus `Retry-After`-aware backoff on 429/5xx. The backtest has its own `_kalshi_get` backoff because the public API 429s under bulk load.

**No GRIB2 anywhere, and this is deliberate.** The system takes already-downscaled station-level guidance rather than decoding raw model grids, because settlement is a specific ASOS site's daily max — which is exactly what NBM/MOS produce. Documented rationale in `forecast_ingest.py`.

| Source | Endpoint | Purpose |
|---|---|---|

| **AviationWeather** | `aviationweather.gov/api/data/metar` | live METAR polling (default source) |
| **IEM ASOS archive** | `mesonet.agron.iastate.edu/cgi-bin/request/asos.py` | historical hourly obs — climatology, intraday curves, backtests, settlement truth |
| **IEM ASOS 1-minute** | `.../cgi-bin/request/asos1min.py` | 1-min spike max (opt-in, off; lags ~1 h) |

**Settlement stations (verified against live Kalshi rules):** NY→KNYC, CHI→**KMDW (Midway, not O'Hare)**, MIA→KMIA, AUS→KAUS, DEN→KDEN, LAX→KLAX, PHIL→KPHL. KORD and KBOS are carried for corroboration/observation only.

## 3. Core mathematical & analytical logic

### 3.1 Strike exceedance — truncated normal

The settling quantity is the *daily maximum*, which is monotonic non-decreasing. So the forecast distribution is a normal **truncated below at the temperature already observed today**:

```
P(final_max >= strike) =
    1                                                    if strike <= observed_max
    [1 - Phi((strike - mu)/sigma)] /
    [1 - Phi((observed_max - mu)/sigma)]                 otherwise
```

`mu` = max of forecast hourly temps over the LST climate day. `sigma` grows with lead time. Kalshi markets are **range buckets** (floor/cap), not simple `>= X`, so bucket probability is a difference of two exceedances; all three shapes (tail-high, tail-low, interior) are handled.

### 3.2 The 15-model shadow ensemble

Every market/day logs 15 probabilities as shadow predictions, graded by Brier and by backtest P&L:

- **Base:** `current` (NWS gridpoint), `nbm`, `gfs_mos` (IEM station MOS), `ensemble` (mean, sigma widened by member disagreement), `climo`, `blend`
- **`_bc`:** bias-corrected variants (per-station rolling forecast-vs-observed bias)
- **`_id`:** intraday-sharpened variants, plus standalone `intraday`

**Intraday sharpening** (`intraday.py`) learns per-LST-hour *remaining rise* = `daily_max − running_max_at_h` from a windowed multi-year IEM sample, giving `daily_max ~ Normal(running_max + mean_rise[h], std_rise[h])`.

> **Do not "fix" the blend to the Bayesian product rule.** `blend_normal` takes a precision-weighted mean but the **sharper of the two sigmas**, not `sqrt(1/(1/sa² + 1/sb²))`. The two errors describe the same air mass; the product rule would manufacture confidence.

### 3.3 Probability recalibration — isotonic / PAVA

`calibration.py` implements Pool Adjacent Violators in ~20 lines of pure Python (no sklearn). Diagnosis it exists to fix: the models are well-calibrated *in aggregate* (Brier 0.14–0.19) but the "take the biggest apparent mispricing" rule systematically selects cheap longshot buckets where the models are overconfident — ≤20¢ YES entries hit ~2%. Root cause is a **sigma-model miscalibration** (a ~4.5 °F sigma smears probability across many adjacent 2 °F buckets), not a market inefficiency.

Fit is always chronologically split (train on the earlier window, score on held-out). Out-of-sample result: ~72% loss reduction, **still net-negative**. Live use is opt-in and currently off.

### 3.4 Sizing & risk

`RiskManager` is the single gate every order passes through. Four invariants: **limit orders only** (market orders are structurally impossible in the type model *and* rejected here), per-market bankroll cap, price sanity `[1,99]`, per-order clamp.

**Fractional Kelly** for a binary contract costing `c` and paying $1:

```python
f_star = (win_prob - c) / (1.0 - c)          # Kelly wager fraction
count  = floor(kelly_fraction * f_star * bankroll_usd / c)
```

**Correlated-group cap:** all buckets of one station/day share a `group_key` (`KXHIGHNY-26JUL21-B90.5` → `KXHIGHNY-26JUL21`), so total exposure across a day's mutually-exclusive buckets is bounded. Both Kelly and the group cap are opt-in and currently off.

**Fee model** (`fees.py`) — Kalshi charges on execution, not settlement:

```
fee = ceil(coefficient * contracts * P * (1 - P))     # coefficient 0.07, P in dollars
```

Fees peak near 50¢ and vanish at the extremes — which is why lock-in trades near 98¢ are barely taxed while mid-book model-edge trades are not. The edge test is fee-aware: a nominal 15% edge that fees would erase is not taken. **There is no maker/taker split in this model** (see §6).

### 3.5 Strategy logic

**Strategy 1 — deterministic lock-in.** Because the daily max is monotonic: once `T_max` exceeds a bucket's cap it can never settle YES (certain NO); once `T_max` reaches the floor of a tail-high bucket it must settle YES. Interior buckets are never deterministically YES intraday. Near-riskless, event-driven, infrequent.

**Strategy 2 — model edge.** Trade when model probability beats market price by ~15% after fees. Fee-adjusted limits are computed by the shared `edge_limit_prices()`, then either crossed or (if passive were enabled) rested.

**Deterministic lock-in** — `models.py:289`

```python
def deterministic_lock_in(self, observed_tmax_f: float) -> Optional[tuple[Side, Action]]:
    """The certain (side, action) given the observed running max, else None."""
    lo, hi = self.floor_f, self.cap_f
    if hi is not None and observed_tmax_f > hi:
        return (Side.NO, Action.BUY)        # max climbed past the cap -> certain NO
    if hi is None and lo is not None:       # tail-high bucket -> certain YES
        hit = observed_tmax_f > lo if self.kind == STRIKE_GREATER else observed_tmax_f >= lo
        if hit:
            return (Side.YES, Action.BUY)
    return None
```

**Fee-adjusted edge limits** — `arb_engine.py` (shared by the live engine and the backtest, so the simulation can never drift from live pricing)

```python
def edge_limit_prices(model_prob, threshold, coeff, calibration=None):
    """(buy_limit, sell_limit, yes_prob, no_prob) for one model-edge decision."""
    yes_prob = calibration.apply(model_prob) if calibration else model_prob
    no_prob  = calibration.apply(1.0 - model_prob) if calibration else (1.0 - model_prob)

    gross = (yes_prob - threshold) * 100.0
    buy_fee = fee_fraction_per_contract(clamp_price_cents(int(gross)), coeff) * 100.0
    buy_limit = clamp_price_cents(math.floor(gross - buy_fee))

    gross = ((1.0 - no_prob) + threshold) * 100.0
    sell_fee = fee_fraction_per_contract(clamp_price_cents(int(gross)), coeff) * 100.0
    sell_limit = clamp_price_cents(math.ceil(gross + sell_fee))
    return buy_limit, sell_limit, yes_prob, no_prob
```

**Fractional Kelly** — `risk_manager.py:99`

```python
@staticmethod
def kelly_count(win_prob, per_contract_usd, bankroll_usd, kelly_fraction) -> int:
    c = per_contract_usd
    if not (0.0 < c < 1.0) or bankroll_usd <= 0 or kelly_fraction <= 0:
        return 0
    f_star = (win_prob - c) / (1.0 - c)
    if f_star <= 0:
        return 0
    return max(0, math.floor(round(kelly_fraction * f_star * bankroll_usd / c, 9)))
```

**Fee model** — `fees.py`

```python
def fee_cents(price_cents: int, count: int, coefficient: float = 0.07) -> int:
    if count <= 0:
        return 0
    p = price_cents / 100.0
    raw_cents = coefficient * count * p * (1.0 - p) * 100.0
    return int(math.ceil(round(raw_cents, 9)))   # round kills float noise before ceil
```

### Not working / net-negative

- **Strategy 2 loses money.** Best model ≈ **−$3.80/trade** (100 contracts) after the look-ahead fix below. Diagnosed cause is longshot over-selection, partly fixed by calibration (~72% loss reduction out-of-sample) but **still negative**. It stays shadow-only.
- **`trades` and `open_limit_orders` are empty (0 rows).** Dry run fills nothing. Any consumer joining fills is dead by construction — this already silently killed the Brier leaderboard and `WA_TRADING_MODEL=auto` for the whole run, until the reconciler was changed to grade every *shadow-predicted* market rather than only filled ones.

### Known bugs & recently-corrected assumptions

1. **TOP ITEM — `metar_ingest` spike guard truncates `daily_tmax`.** A `>5 °F` jump requires re-confirmation within 5 minutes, but METARs arrive hourly, so at stations whose normal morning warm-up exceeds 5 °F/h the guard rejects ordinary diurnal warming and the validated max freezes near the morning value. Short by ≥2 °F on **21% of city-days**; mean **−11.5 °F at DEN, −7.2 °F at AUS**; MIA/LAX perfect. This corrupts Strategy-1 lock-in and the intraday model's input, and is a larger error source than model choice (which spans only $3.42/trade). **Not yet fixed.**
2. **Look-ahead bias in the backtest — found and fixed 2026-08-23.** `_candle_series` passed `period_interval=60` believing it was seconds; Kalshi counts **minutes**, so backtests read *hourly* bars and used that bar's close — the quote up to 59 minutes *after* the prediction. Fixed to true 1-minute bars. Cost of the fix on the taker baseline: **−$2.99 → −$3.80/trade**. Any Strategy-2 figure in the repo history dated before 2026-08-23 is optimistic by roughly that much.
3. **Settlement authority changed to The Weather Company** (discovered + verified 2026-08-21). TWC's published daily max equals the hourly-METAR max already ingested on **147/147 station-days** (mean diff 0.00 °F). Consequences: the NWS CLI runs +0.80 °F warmer and lands in a different bucket 38% of the time; `WA_ENABLE_1MIN_LOCKIN` is therefore **definitively harmful** (it pulls `T_max` toward the CLI basis) and stays off; `divergence.py`'s premise is **inverted** and its `delta_f` is not an edge; and for MIA/AUS/DEN/LAX/PHIL, Kalshi and Polymarket now share both station *and* basis, so the cross-venue settlement edge at those five cities is gone — only NYC/CHI survive.
4. **Passive placement measured and rejected 2026-08-23.** `WA_ENABLE_PASSIVE_MODEL_EDGE` had shipped but never been measured. Measured spread on entered markets is only **2.04¢ mean / 1¢ median** (ceiling $1.04/trade vs a $4+ loss). Same-side execution delta is negative in 24/24 configs on the held-out window. Reason: the taker rule is *already* patient — it only fires once the ask has fallen inside the fee-adjusted limit, so a resting bid forfeits the wait, which is worth more than the spread. Flag stays off.

### Where an external contribution has most leverage

1. **Fix the METAR spike guard** (rate-limit in °F/hour rather than a flat °F step). Largest single measured error source; blocks running Strategy 1 live.
2. **Re-derive the intraday sigma floor** from TWC preliminary→final revisions. It binds on every late-day market, so it directly sets model output.
3. **Entry *timing*, not execution.** Evidence suggests `first_qualifying_edge` (enter at the *first* qualifying snapshot) is the wrong rule and waiting for forecast convergence is better — but n is thin and it overlaps Strategy 1 conceptually.
4. **Not model swaps.** All 15 variants span only $3.42/trade while the threshold alone spans ~$5.6. An oracle forecast earns +$38.21/trade through this exact rule and fee model, so the plumbing converts skill fine. Frontier AI weather models (GraphCast/GenCast/Aurora/AIFS) are global **gridded** ~0.25° products; this needs station-level daily max at a specific ASOS site, which is what NBM/MOS already downscale to.
